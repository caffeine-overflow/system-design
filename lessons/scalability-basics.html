READ · WHAT SCALABILITY IS

What scalability actually means

Read this first. It defines every word the rest of the lesson builds on.

THE CORE IDEA

Same match, bigger crowd.

To scale means a system handles growing load — more users, more requests, more data — without getting slower or breaking. Load is simply the demand placed on the system: the size of the crowd.

Picture a football stadium. Hosting 500 fans for a match is easy: one gate, a few stewards. Hosting 50,000 for the same match is the same game, but you need more turnstiles, more stewards, wider concourses, and a plan for everyone leaving at full time. Cram 50,000 people through the 500-fan setup and queues explode — that is a system that does not scale.

SCALE UP · VERTICAL

One bigger stadium

Make the single machine stronger: more CPU, more RAM. Fast to do and easy to reason about. But there is a ceiling — you cannot build an infinitely big stadium — and one fire alarm still empties the whole place.

SCALE OUT · HORIZONTAL

More turnstiles

Add more identical machines and split the crowd across them. A load balancer is the head steward waving fans to the shortest open turnstile: software that distributes incoming requests across healthy servers. This is the default way systems scale.

THE WORDS YOU'LL NEED

Throughput, latency, bottleneck — in one breath.

Throughput is how much work gets done: requests per second, or fans through the turnstiles per minute. Latency is how long one request takes: one fan's wait at the gate. A gate system that moves 10× the crowd but makes every fan wait five minutes did not scale — it just got bigger and worse. The bottleneck is the slowest part that caps everything else: the single narrow tunnel every fan must funnel through, no matter how many turnstiles you open.

THE TWO SIGNALS

Throughput tells you how much. Latency tells you how well.

Think of the stadium again: throughput is fans through the turnstiles per minute; latency is one fan's wait at the gate. A system that handles 10× traffic but takes five seconds per request did not scale — it just got bigger and worse. And an average can hide the requests that feel painfully slow, so engineers also look at percentiles.

What does p99 mean?

Line up 100 requests from fastest to slowest. The p99 is the response time of request 99. If p99 is 800 ms, 99 of 100 requests finished within 800 ms; the slowest 1 took longer.

VERTICAL

Buy a faster barista

More CPU and RAM on one machine — one bigger stadium instead of a small one. Fast to ship, easy to reason about, but expensive near the ceiling — and still one machine that can fail.

HORIZONTAL

Open more counters

Add servers behind a load balancer — more turnstiles for the same crowd. More coordination, but better headroom and survivability. This is your default interview posture.

THE REAL DIVIDING LINE

Stateless servers are easy to copy.

Picture a turnstile operator who keeps the guest list in their head. They can't be swapped mid-shift, and if they walk away, the list walks away with them. Stateless servers are the opposite: keep sessions in a shared store like Redis, files in object storage, and durable counters in a shared database — so any server can handle any request, and losing one server loses nothing. Sticky routing (pinning each user to one server) is a stopgap for when you haven't done this yet, not a destination.
